### Load context

**You own what this session knows before it advises. Read what was decided. Don't rediscover it and don't reopen it.** This runs when j-mode is loaded without a task. It ends with a reply, not with work.

1. Check the handoff against the repo. A start hook may have put the last handoff in your context. With none, read the newest handoff note the project keeps (`.remember/remember.md` or its own equivalent). Run the check its state line names, or `git status`, `git log` and the remote refs, and say where the note and the repo disagree.
2. Find the decisions behind each open item. For every open or next item, locate where its decisions are recorded: the spec or plan the handoff names, the project's decision log, its instruction files. Read a spec's goal and its list of the owner's decisions in full. An item a recorded decision answers is settled, so don't raise it again.
3. Query memory with the open items. When a memory tool is present (Hindsight's `hindsight_search_pages`, the project's memory index), search once per open item in that item's own words, never one generic question, and read the top page in full. Memory is a lead, so check a claim against the code before you repeat it. With no memory tool, say so.
4. Read the prior transcript only to fill a gap. When an open item's reasoning is in neither the handoff nor a decision record, read the last session's transcript as **Session pickup** step 1 describes, in a subagent. Otherwise skip this step.
5. Name the tools this repo expects. From the project's instruction files and rules, say which code navigation tool comes first, what wraps shell output, and where the catalog of skills and MCP servers is. Load none of them yet.

**Reply:** the verified state, then each open item with the decisions in force and where each is recorded, the tools you will reach for, and what you did not check. Ask nothing a recorded decision answers. Then wait for the task.
