# Version strategy

What each kind of version emphasizes, and how many versions to keep for common
situations. Every version still pulls from the one master.

## Categories by target role

| Role                 | Emphasize                           | Skills to highlight                      |
| -------------------- | ----------------------------------- | ---------------------------------------- |
| Product management   | Strategy, roadmap, metrics, stakeholders | Product tools, analytics, user research |
| Software engineering | Technical projects, systems, code   | Languages, frameworks, tools             |
| Data science         | Analysis, ML, statistical methods   | Python, SQL, ML libraries                |

Apply the same split (what to emphasize, which skills to surface) to any other
role family the user targets.

## Categories by industry

| Industry             | Emphasize                         | Tone                                   |
| -------------------- | --------------------------------- | -------------------------------------- |
| Tech and startups    | Innovation, growth, scrappiness   | Modern, direct, achievement-focused    |
| Enterprise/corporate | Scale, process, collaboration     | Professional, structured, comprehensive |
| Finance              | Analysis, compliance, accuracy    | Conservative, precise, credentialed    |

## Categories by seniority

- **Individual contributor:** execution and technical skills, detailed project
  descriptions, technical accomplishments.
- **Manager:** team leadership and development, cross-functional
  collaboration, business impact metrics.
- **Executive:** strategic leadership, P&L responsibility, organizational
  transformation.

## Common situations

### Applying to similar roles

- Create one well-tailored version for the role type.
- Make minor adjustments for each company.
- Track which variation went where.

### Applying to different role types

- Create a separate base version for each role type.
- Keep the folder organization clear.
- Each base pulls from the same master.

### High application volume

- Create two or three strong category versions.
- Use "general" versions for quick applications.
- Reserve deep tailoring for the top choices.

### Career transition

- Create a transition-focused version.
- Emphasize transferable skills (see the **career-changer-translator** skill).
- Keep the original-industry version as a backup.
