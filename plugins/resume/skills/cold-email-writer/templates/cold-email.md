# Cold email layout

Deliver the final email in a single plain code block in this layout, with no
commentary inside the block:

```
Subject: Quick intro - [First Last]

Hi [Name],

[Email body]

[First name]
[email]
```

## Skeleton wording for the body

Adapt these to the user's facts and voice. Drop the two optional parts when
they don't apply, and drop or rewrite any skeleton sentence that is not true
of the user (currently employed, production work, a side project).

**Hook**

```
I just came across [Company] and ended up spending more time on it than I
expected. [One specific thing that caught their attention - a stat, a product
decision, a market insight from the job description or website]
```

**Location disclosure** (only if in a different country)

```
Before you read further, I should mention I'm based in [country]. But if we
both feel there's a strong fit, I'd be open to figuring things out.
```

**Experience gap** (only if the role lists more years)

```
The role mentions [X] years of experience - I'm at [Y], but the work I've
shipped is production-facing and I'd rather you judge that directly.
```

**Body**

```
A bit about me: I currently work at [Company], [one line on what the company
does], where I [what they actually do there - not a job title]. Before that I
worked with teams in [region], mostly around [relevant domain].

On the side I've been building [Project] ([link if applicable]) - [one line:
what it is and one proof point like "got to paying clients" or "20K
downloads"].
```

**Connection**, general or more specific

```
I think you're looking for [what the role actually wants] - that's the kind of
work I've been doing, and honestly I feel like I'd be a strong fit.
```

```
My stack maps naturally to yours - [specific tech overlap]. But more than the
stack, it's the [domain/problem] that I'm genuinely interested in.
```

**Portfolio link**

```
More about me: [portfolio URL]
```

**Closing**

```
I'm currently at [Company] and open to what's next. I think my experience
lends nicely to what you're building - so I think we'd both get something out
of a conversation.
```

After the code block, list any estimate or assumption the user still needs to
confirm.
